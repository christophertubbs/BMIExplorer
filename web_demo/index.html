THE EXPERIMENT RECORD

Every call tells a story.

    BMI REQUIRED

    Methods, variable-to-grid identity, geometry, topology and copy/reference semantics follow the BMI interface.

    C++ PARITY

    Caller-allocated typed memory. Exact lengths. No implicit cast, reshape or broadcast. Errors happen before writes.

    EXPLORER POLICY

    TypedArrays, rank/axis applicability, fixed timesteps and empty point topology are explicit teaching choices.

    YOUR FIRST EXPERIMENT

    Start with a grid.
    End with a mental model.

    1. Choose a variable. The left inventory shows its grid, location and dtype. The plot and value strip refer to the same storage.
    2. Ask for geometry. Try get_grid_spacing on a uniform grid, then on rectilinear. Same method, different applicability.
    3. Change memory. Click a node, edge or face; write its value through an exact typed indexed call.
    4. Keep a copy and a reference. Edit both, then step the model. Watch which buffers change together.
    5. Break a contract. Try a plain array, wrong width, wrong length or out-of-range index. Read what was rejected and why.

    Picking a grid keeps the same model. Switching the demonstration model or resetting creates a new one. Retained JavaScript arrays may outlive that owner; C++ pointers do not gain that lifetime guarantee.

    3D views are rotatable projections. Structured plot lines are derived guides, not extra BMI connectivity. JavaScript cannot express strided TypedArrays or revoke an existing reference; no raw-pointer safety is simulated.
